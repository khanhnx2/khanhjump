# Extended Khanh Jump to 20 Levels with Boss Fights

**Date**: 2026-07-12 19:30–23:00  
**Severity**: Low  
**Component**: Game levels, boss fight system  
**Status**: Resolved (uncommitted for playtesting)

## What Happened

Completed full implementation of levels 11–20 (duplicate layouts 1–10 with boss fights). Created three new modules (`boss-level-data.js`, `boss-fight-state.js`, `boss-renderer.js`) implementing player x-locked jump-only mode, 0.5s infinite auto-fire, ground-band bullet dodge mechanic, and sequential boss queue. Verified via headless node + live browser (desktop/mobile).

## The Brutal Truth

Smooth execution — the 4-phase plan structure held perfectly. Two environmental gotchas midway through verification derailed focus for 45min total: (1) Big boss clipping 375px mobile viewport (camera had to shift +1.5 tiles), (2) service worker cache-first served stale `main.js` during dev loop. Both were "wait, what?" moments, not logic bugs. The SW cache issue in particular is friction we'll face repeatedly in dev cycles until we cache-bust via content-hash at build time (already wired for Android, but offline testing kept re-serving old code).

## Technical Details

- **18-check headless simulation**: stubbed Image/window, all asset loading paths validated.
- **Mobile clipping root cause**: viewport 375px, boss sprite 96×96 at camera 0 renders off-canvas. Solution: shift camera +1.5 tiles during boss phase.
- **Stale cache root cause**: service worker cache-first policy + manual dev changes to `main.js` → browser served cached version. Workaround: unregister SW in DevTools. Permanent: content-hash bust at Android build time.
- **Code review fixes**: (1) bullet cull bounds widened to `BOSS_DISTANCE*4` (was 2×), (2) `defeatedBoss` initialized `null` not `false`, (3) `package.json` test script fixed — old `node --check js/*.js` only validated first file (latent weakness).

## Lessons Learned

1. **Service worker friction in dev is real.** Even with content-hash caching for prod, local testing without cache-bust is painful. Consider build-time injection of `.env.BUILD_HASH` for client to invalidate on startup.
2. **Headless + live testing catches complementary bugs.** Headless validated logic; live caught viewport/rendering edge cases.
3. **npm script `node --check` bug was hiding.** Test script only checked first `.js` file. Switched to glob `js/*.js` — caught zero syntax errors, but demonstrates brittle automation when names matter.
4. **Game state bloat risk.** Three new modules + `boss` game state kept complexity contained. Good sign: boss phase cleanly isolated.
